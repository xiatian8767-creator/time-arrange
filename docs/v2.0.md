# 星课表 2.0.0-beta.1

分支：`codex/v2.0`。升级基线为当前 1.2.5，保留原签名，versionCode 9。未发布 GitHub Release，也不覆盖现有下载站的 1.2.5。

## 用户流程

1. 离线功能照常使用。设置 → 注册/登录 → 填写 HTTPS API 根地址、用户名和密码。用户名 3–32 位字母数字下划线，密码 10–128 字符；注册另需昵称。
2. 首次登录明确选择使用云端，或将访客/此账号本机副本上传。退出登录恢复访客空间，不把另一账号的待办混入。
3. 在线期间编辑后自动尝试同步，前台每 45 秒刷新。失败保留本机修改。检测到双方修改则暂停覆盖，可先导出备份，再选本机或云端整份数据。
4. 搭子课表 → 联网申请，精确搜索对方的 12 位 ID、发送邀请。对方在同入口接受。每人最多一名在线搭子。支持拒绝、撤回、解绑。原本的配置导入仍可用，是静态离线副本，与在线关系无关。
5. 浮动 ✦ 可拖动，位置保存在设备。进入 AI → 配置官方地址、模型与个人 Key。DeepSeek 默认 `deepseek-flash`；Qwen 默认北京兼容接口与 `qwen3-vl-plus`，可换官方业务空间地域地址。
6. 勾选允许提供给 AI 的数据；待办默认不勾选。照片选取或拍照后，点击发送才上传到所选模型。AI 返回建议，用户逐项核对前后内容与不确定信息，确认后统一写入；任何校验失败、取消或期间本机变化都不会应用该建议。

## 数据位置与隐私边界

- Android 应用私有目录 `shared_prefs/star_schedule.xml`：当前 `data` 为版本 2 JSON，包含 slots / courses / todos；`partner` 为导入的静态课表（无 todos）。不是三个独立的物理 JSON 文件。
- `active-scope` 为当前数据空间，访客为 guest；账号空间以 HTTPS origin 与用户 ID 组合标识。`document-<scope>`、`partner-<scope>` 保留切换前的副本。相同 ID 在不同服务器不会混用。
- `vault-cloud`：Keystore AES-GCM 加密的会话、版本号及上次已同步内容；`vault-ai`：同样加密的提供方配置与 Key。系统备份关闭；Key 不进入 `data`、JSON 导出或服务器。
- 待办去重状态按账号隔离；切换账号取消原账号已显示通知，重新计算当前账号提醒。
- 在线搭子课表只在内存保留；退后台、联网失败或解绑时清掉在线显示，恢复原静态副本（如有）。远端解绑的发现依赖下一次轮询，不能追回已经看过或自行保存的内容。
- 服务端 PostgreSQL `users.document` 保存本人的 slots / courses / todos；revision 用于并发控制。**待办是权限隔离，不是端到端加密，服务器管理员仍有数据库访问能力。**
- 账号资料只包括用户名、昵称、随机公开 ID 与 Argon2id 密码哈希；无短信/邮件服务或自助密码找回。请妥善保管密码。
- 模型消息只在本次界面会话内存；图片缩放压缩到最长边不超过 2048，最大 2 MB JPEG。相机使用私有临时文件，处理后删除；不存到服务器。切换账号清空聊天和图片。
- API Key、照片和明确勾选的数据直接发送给所选模型服务商；服务商处理规则和 API 费用另计。切换数据勾选时不再发送此前对话历史。

## 接口约定

UTF-8 JSON，前缀 `/api/v1`。鉴权 `Authorization: Bearer <accessToken>`。成功返回业务 JSON，失败 `{ "detail": "可读错误" }`；422 不回显非法输入中的密码/密钥。请求体最大 1 MiB。

| 方法 / 路径 | 请求 | 响应 |
| --- | --- | --- |
| POST /auth/register | username,password,nickname | accessToken,refreshToken,expiresIn,user |
| POST /auth/login | username,password | 同上 |
| POST /auth/refresh | refreshToken | 轮换后的同上；旧刷新凭证失效 |
| POST /auth/logout | 无 | ok；注销当前会话 |
| GET /me/data | 无 | user,revision,document（初始为 null） |
| PUT /me/data | baseRevision,document | revision；不匹配返回 409 |
| GET /users/lookup?userId=… | 精确公开 ID | userId,nickname；不返回账号登录名或数据 |
| GET /partner | 无 | partner,incoming,outgoing |
| POST /partner/invitations | userId | id,status；重复待处理邀请返回同一 ID |
| PATCH /partner/invitations/{id} | action:accept/reject/withdraw | ok；仅收件人同意/拒绝，仅发件人撤回 |
| DELETE /partner | 无 | ok，解除双方关系 |
| GET /health | 无 | ok,version；验证数据库可用 |

`user` 为 `{userId,nickname}`。`partner` 为 null 或 `{userId,nickname,revision,schedule}`，schedule 仅含 version / slots / courses；无课表时为 null。incoming/outgoing 项为 `{id,user,createdAt}`，createdAt 为毫秒。

同步示例：

```json
{
  "baseRevision": 0,
  "document": {
    "version": 2,
    "slots": [{"id":"s1","start":"08:00","end":"08:45"}],
    "courses": [{"id":"c1","day":1,"start":"s1","end":"s1","name":"数学","room":"101","note":"","color":"#6b9cf4"}],
    "todos": [{"id":"t1","title":"报告","dueAt":1800000000000,"createdAt":1790000000000,"priority":"normal","note":"","completed":false,"remind":true}]
  }
}
```

作息 1–24 段、课程 ≤400、待办 ≤500；有序时间不重叠、同日课程不冲突、ID 唯一。服务端严格校验类型与未知字段。课程 day 为 1–7；start/end 是 slots ID，不是时间文本。待办时间为毫秒。活动段可用 `kind:activity,label`。

访问令牌 15 分钟，刷新令牌 30 天、使用即轮换；数据库只存凭证 SHA-256 哈希。联网重新失败时不强制清除本机数据。限流为单进程内存窗口（重启重置），部署固定单 worker；密码计算最多并发 2 个以保护小型服务器。事务锁保证多人同时接受邀请最多一对绑定；更新 JSON 用数据库条件更新，不依赖客户端时钟。

## AI 契约

AI 返回 `{message,warnings,operations}`，客户端只接受白名单操作：course / todo 的 create、update、delete，及 schedule.replace。单次最多 100 项；模型无脚本执行、文件系统或服务器调用能力。

create/update 格式 `{type:"todo.create",id:"唯一ID",value:{...}}`，value 不允许 id 或未知字段；delete 仅含 type/id。schedule.replace 带完整 slots/courses（每门课程含 id），永不替换 todos。先复制数据、应用提议、校验整份 JSON，然后预览；确认时检查账号代次及基线内容未改变，单次本地保存成功才更新 UI 和同步。

原生端仅允许 HTTPS。AI 请求仅允许指定供应商官方域名，不跟随重定向；不设自签名证书绕过，不把 Key 发给用户随意填写的第三方域名。WebView 本身仍禁止直接网络访问、外部导航和文件访问。

官方接口参考： [DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)、[Qwen 视觉兼容接口](https://help.aliyun.com/zh/model-studio/qwen-vl-compatible-with-openai)。真实 Key 可用性、模型权限、地域、额度需实际账号验收。

## 部署

`compose.v2.yaml` 只建立一个 API 和一个 PostgreSQL 实例，不开数据库公网端口；API 仅 `127.0.0.1:18080`。数据卷 `xingke-v2_data` 持久保存数据。`.env` 使用随机数据库密码，禁止进 Git。`backend/deploy.sh` 仅用于 `/opt/xingke-v2`，不会操作原下载站。

```sh
# 在专用目录配置 DB_PASSWORD 后
docker compose -f compose.v2.yaml up -d --build
curl http://127.0.0.1:18080/api/v1/health
# 只创建随机独立 schema 的 PostgreSQL 并发验收，完成后清理该测试 schema
docker compose -f compose.v2.yaml exec -T api python -m backend.verify_postgres
```

上线前必须配置可信 HTTPS 反向代理与自动续期，确认阿里云安全组、备案/应用相关要求；再将入口填入客户端。需要限流反向代理层限制请求体与访问频次，不记录 Authorization 和请求体。当前 API 不信任任意 X-Forwarded-For，不得随意改为信任所有代理；如配置可信代理，需明确其地址。

IP 技术上可使用 HTTPS，证书需包含该 IP。Let’s Encrypt IP 证书约 160 小时，必须自动续期：[官方说明](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)。IP 不能替代备案；内地服务器 IP 对外服务仍有要求：[阿里云说明](https://help.aliyun.com/zh/icp-filing/basic-icp-service/product-overview/icp-filing-requirements-for-a-regular-website)。此测试版不自动开放公网端口或更改已有站点。

运维需自行安排数据库加密备份、留存与恢复演练。备份可在服务器执行 `docker compose -f compose.v2.yaml exec -T db pg_dump -U xingke -Fc xingke > xingke-backup.dump`；恢复只能选明确的隔离数据库，避免误覆盖。后续 schema 改动应引入版本化迁移，不能依赖 create_all 修改既有列。

## 验收与限制

- `python -m pytest backend/test_api.py -q`：SQLite 功能测试，账号、同步冲突、刷新轮换、私有待办、邀请权限、解绑、格式/大小限制、限流。
- `node --test qa/ai-core.test.cjs tests/core.test.js`：AI 原子校验与原课表回归，原 tests 目录为本地历史测试，qa 为新增可提交测试。
- `node qa/v2-ui.cjs`：需要 Playwright 和本机 18765 测试 API。Android 桥为模拟实现、API 为真实测试服务、模型回复为模拟；验证账号隔离、冲突、搭子、AI 确认/取消/失效、拖动和窄屏。
- 真实 Android 构建使用原 `build.ps1`，release 关闭 WebView 调试，保持原签名。
- 当前没有真实 API Key，不能声称已验证付费模型、拍照识别准确率。不能把内部部署等同于手机已可公网登录。
- 暂无自助找回密码/注销账号、多搭子、推送、后台自动同步、自动合并、端到端加密。这些不是本轮确认的交付范围；面向陌生用户公开前需要进一步安全、合规和运维审查。
