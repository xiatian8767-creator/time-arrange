# 星小助配置与计费

入口：后台“星小助系统”，内部区分 API 列表、用户访问记录、统一计费规则。添加API后，还须在规则页面启用总开关；两个启用状态相互独立。

## API 池

- 支持多个 DeepSeek / Qwen Key；编辑时密钥留空保留原值，接口不读回Key。Qwen地域应匹配开通地域，仅对真正支持图片的模型勾选图片能力。
- 同一会话优先使用同一个健康且具备能力的API，故障再切换；旧客户端未提供会话编号时按请求轮询。Key不下发客户端。
- 鉴权/额度问题一般冷却15分钟，限流及上游HTTP错误一般1分钟，网络/格式错误一般30秒。后台可解除冷却；内容安全拒绝不通过换供应商绕过审核。
- 单个API超时可设5–300秒，整次路由预算约300秒。长回复建议180秒，不保证一次能尝试整个API池。
- 访问记录可按用户、状态筛选，展示用量、扣费与切换路径，不展示用户原图和对话正文。

## 客户端与限制

上下文组装、图片任务记忆、建议解析、字段校验、预览及确认保存在客户端；服务端只负责转发、鉴权、密钥容错和星币结算，不执行课表/待办操作。确认前不写入，清空对话或切换账号释放会话上下文。

最大输出可配置至131072 token，实际受所选模型、超时、余额与费用上限限制。图片最多10张，文本上下文上限1MiB，代理请求上限4MiB；不是无限历史。已知模型能力映射见 backend/assistant.py，接入新模型前核对官方参数。

## 统一计费

所有API共用一套规则，不分别按供应商定价。按最终成功回复的实际usage核算，包含系统上下文、历史、图片及输入输出，而非仅按用户输入字数。

`星币 = ceil((缓存命中token×命中价 + 未命中输入token×未命中价 + 输出token×输出价) / 1000000 × 倍率 × 每元星币数)`

初始配置：倍率5，每元100星币；高峰命中/未命中/输出参考价为0.04/2/8，空闲为0.02/1/4（人民币元/百万token）。这是初始化参考值，实际以后台配置及历史请求保存的规则快照为准，不把它当服务商永久价格表。

自动时段使用北京时间工作日09:00–12:00、14:00–18:00，并排除后台配置假期；跨年须更新日历或改固定时段。更改价格只影响后续请求。

- 发起请求先预留不超过余额和单次上限的星币，完成后结算并返还余量；预留余额不能同时赠送或消费。
- 失败切换不叠加扣费。上游失败、无有效用量、截断、超余额或费用上限时返还本次预留。
- 同一请求编号和相同内容复用回执，不重复扣费。客户端最多自动校正一次，原回复与校正合并未取整费用后结算差额。
- 完成的模型回复仍按用量收费；用户未保存或建议不能应用不等于模型请求失败。
- 未完成预留超过10分钟可恢复；单进程启动时恢复未完成预留。当前只支持单API容器、单worker，不直接扩成多实例。
- 每用户每分钟5次、每天100次新请求，单用户最多一个进行中请求，服务端同时最多3次。

## 密钥、数据与恢复

Key用Fernet加密保存在 assistant_api_keys；主密钥 /opt/xingke-v2/ai-secrets/key 只读挂载到 /run/secrets/starorbit-ai-key。不得覆盖、重新生成或提交Git，数据库与主密钥分别安全备份并配套恢复。

assistant_billing_rules 保存规则；assistant_api_attempts 保存尝试路径；assistant_calls 保存幂等回执、用量和规则快照；star_transactions 保存实际扣费。回执包含模型回复以支持断线查询，不能据“后台不展示”推断数据库完全不保存回复。

旧 assistant_config 仅作兼容迁移。回滚旧版程序前核对表结构与密钥读取方式，不能用旧代码直接读取新API池。部署边界见 deployment.md；不要通过删除用户表、钱包或主密钥实现回滚。
