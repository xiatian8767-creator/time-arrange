# 星小助后台配置与星币计费

配置入口：后台工作台的“星小助 API 列表”“星小助访问记录”“星小助计费规则”。需要现有管理员登录。先添加 DeepSeek / Qwen API，再在统一计费规则中启用服务。编辑时密钥留空保留原密钥，管理接口不能读回 Key。多 Key 轮询及迁移说明见 [API 池说明](assistant-api-pool.md)。不要将 Key 发到聊天或提交到 Git。

默认模型为 `deepseek-flash`，对应 DeepSeek-V4.1-Flash-1017。支持文字和图片；客户端个人 Key/Qwen 选择入口在新版中移除，旧版个人 Key 不会上传到服务器。新版请求统一通过平台接口。

## 初始价格

以下为人民币元 / 百万 token，参考2026-10-20官方文档：

| 时段 | 缓存命中输入 | 未命中输入 | 输出 |
| --- | ---: | ---: | ---: |
| 高峰 | 0.04 | 2 | 8 |
| 空闲 | 0.02 | 1 | 4 |

倍率5；每元100星币；计费为：

`星币 = ceil((命中输入token×命中价 + 未命中输入token×未命中价 + 输出token×输出价) ÷ 1000000 × 5 × 100)`

例：高峰1000输入token，其中200命中缓存，输出100token：`ceil((200×0.04 + 800×2 + 100×8) / 1000000 × 5 × 100) = ceil(1.204) = 2星币`。空闲同样用量为1星币。

按最终成功API的实际usage计算，包含系统上下文、对话历史、图片、输入和输出；不会按用户输入的字数估算。所有供应商共用上面的同一套价格。服务器固定HTTPS访问DeepSeek或Qwen官方域名，拒绝重定向，客户端不能指定上游URL、费率或扣费数。未接入联网搜索/抓取工具。

时段按请求开始时的北京时间：周一至周五09:00–12:00、14:00–18:00为高峰，周末及配置假期为空闲。默认内置2026年假期，可在后台调整；自动模式跨年需更新日历，或先选择固定时段。更改价格只影响后续请求，历史记录保留规则快照。

官方来源：https://api-docs.deepseek.com/zh-cn/quick_start/pricing/

2026年假期来源：https://www.beijing.gov.cn/cs/gncs/zcwj/202603/t20260327_4568275.html

## 结算与可靠性

- 请求开始前从钱包预留不超过可用余额和单次上限的星币；默认单次上限100星币。模型完成后按实际用量结算，多余部分返还。预留中的星币不能再次送礼或消费。
- 同一请求ID和相同内容复用原回复，不重复请求模型或扣费。请求ID与内容不一致则拒绝。查询接口仅本人可访问。
- 客户端首次建议格式未通过校验时，最多自动校正一次。校正与原回复的未取整费用合并，再计算应补扣的整数差额；不会每次校正都另收最低1枚。
- 上游失败、缺少有效usage、截断、非JSON/不合规回复、超出余额或上限，均返还该次预留并不收费；平台承担此类已产生的上游成本。原回复已成功、仅后续校正失败时，原回复的已结算费用保留。
- 网络断开后可查询原回复，客户端不自动重发新的付费请求。未完成预留超过3分钟，在查询/重试或钱包刷新时恢复；单API进程重启时恢复未完成预留。当前生产为单容器、单worker；不要在未改造恢复机制前做多实例滚动运行。
- 客户端展示的费用取自服务器回执。用户不确认修改课表或待办，也仍需支付已经完成的对话费用。
- 每用户每分钟最多5个新模型请求、每日最多100个，单用户仅一个进行中请求，服务器同时最多3个。

表：`assistant_api_keys`保存加密Key及健康状态；`assistant_billing_rules`保存统一规则；`assistant_api_attempts`保存上游尝试路径；`assistant_calls`保存幂等结果、用量和规则快照；`star_transactions`记录`ai_chat`实际扣费。旧`assistant_config`只用于兼容迁移。管理员访问记录不展示用户照片和对话内容；数据库中的短期回执缓存包含模型回复，以支持断线查询。

## 密钥与部署

Key以Fernet认证加密保存于数据库，主密钥位于服务器`/opt/xingke-v2/ai-secrets/key`，目录root 0700、文件UID10001 0400，仅只读挂载至`/run/secrets/starorbit-ai-key`。管理API仅返回是否已配置，不能读回Key。Git和构建上下文均排除`ai-secrets/`。

首次部署已生成并备份主密钥。不得在后续版本覆盖或重新生成，否则已加密模型Key将无法解密。数据库与主密钥需要分别安全备份。主密钥恢复必须与数据库备份配套。

本次服务更新备份：`/opt/starorbit-ops-backups/assistant-20261020-34b1/`，root受限目录，包含数据库、原后台配置和主密钥备份。新版本只新增表，不更改现有钱包字段。回滚程序可使用原API镜像和原Compose配置；不要删除用户数据表或覆盖现有主密钥。

正常构建可使用`backend/Dockerfile`及更新后的requirements。服务器此次采用预下载的Linux cryptography wheel离线安装，运行镜像`xingke-v2-api:3.4beta.1`。沿用原五个Compose文件的部署命令，只重建Star Orbit API；共享代理仅平滑重载，Fuguang的后端、数据和配置未作修改。

接口：管理员GET/POST `/admin/api/assistant`、GET `/admin/api/assistant/usage`；用户GET `/api/v1/ai/status`、POST `/api/v1/ai/chat`、GET `/api/v1/ai/requests/{requestId}`。POST均沿用对应用户鉴权，后台写入还需CSRF。
