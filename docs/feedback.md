# 网站用户反馈

发布页的反馈按钮指向 `/feedback/`，当前 HTTP 下载站跳转至 `https://8.154.43.154:8443/feedback/`。表单与提交接口使用同一 HTTPS 来源。无需注册，问题描述和联系方式必填，图片可选，最多 3 张。后续统一域名 HTTPS 时，可直接把 `/feedback/` 转发到 API 容器，无需改页面接口。

数据库新增 `user_feedback` 表，应用启动时自动创建，不修改原有用户数据。保存描述、联系方式、经验证并重新编码的 JPEG 图片、状态、时间、处理人、内部备注和修订号。图片直接保存在 PostgreSQL 的该记录中，数据库备份包含图片，不需要可写容器目录。表单客户端压缩，服务端校验最多 3 张、单张上传 180 KiB、请求总量 1 MiB；照片元信息在重新编码时移除。

状态：`pending` 待处理、`processing` 处理中、`completed` 处理完成。后台新增“用户反馈”栏目，支持状态筛选、分页、详情、图片和处理备注。更新采用原有管理员会话和 CSRF 校验，重复提交去重，并发修改冲突需重新打开详情。列表不返回图片内容，图片接口要求管理员登录。

公开提交：`POST /feedback/api`。管理员接口：`GET /admin/api/feedback`、`GET /admin/api/feedback/{id}`、`GET /admin/api/feedback/{id}/images/{index}`、`POST /admin/api/feedback/{id}`。匿名用户不能查询反馈、联系方式或图片。

本次只更新网站和后端，不改变 Android 安装包版本。

验证（2026-10-10）：后端反馈、管理员、账号接口和旧待办兼容测试共 13 项通过。线上 Edge 浏览器从发布页进入反馈页，完成图片压缩上传、提交入库、管理员查看图片、待处理 → 处理中 → 处理完成、刷新后状态保留和退出登录验证。移动端无横向溢出，提交内容以纯文本展示。测试记录在验证后清理。

同日补充：域名及 www 域名的新页面已核对反馈链接与跳转。发布首页和 index.html 添加 `Cache-Control: no-store`，静态资源与 APK 原有缓存行为不变；按钮文案改为“提交反馈”以区别旧页面。已经存在于手机浏览器的旧页面快照仍可能需要重新打开带版本参数的网址。
